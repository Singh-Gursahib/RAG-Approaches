# 12 — Research Paper Workflow

> How experimental artifacts become a publishable paper. Target venue, structure, figure pipeline, statistical reporting standards, reproducibility package, submission process.

---

## 1. Target Venue

**Primary target:** ACL Findings or EMNLP Findings (long paper, 8 pages + unlimited references + appendix).

**Secondary targets** (if scope/timing demands):
- A long-context / RAG-focused workshop (e.g., a TREC RAG track companion, NeurIPS workshop on RAG/long-context).
- arXiv preprint as fallback / pre-publication.

**Why Findings.** This is a comparative + benchmarking paper rather than a single-method-with-novelty paper. Findings tracks at \*ACL venues are well-suited to thorough empirical work that doesn't necessarily introduce a single new model.

The hybrid architectures in `10_HYBRID_PROPOSALS.md` provide enough novel contribution for a main-track submission if execution is strong; the meta-router (#6) is the strongest single novelty claim.

## 4. Contribution Statements (Pre-Committed)

The paper will defend exactly these contributions. Anything beyond is appendix material.

1. **Unified comparative framework.** First (to our knowledge) framework benchmarking ≥ 21 long-context techniques under the same evaluation harness across 7 domains.
2. **Cross-domain Pareto analyses.** Cost-quality and latency-quality Pareto frontiers per domain, with statistical significance.
3. **Six novel hybrid architectures.** Empirical evaluation of routing, cascading, and composition patterns. The meta-router (#6) is the most novel and the headline.
4. **Decision framework.** A reproducible mapping from query/domain features → recommended technique stack, derived from data not intuition.
5. **Open-source artifact.** Full framework, datasets (where licensed), benchmarks, and reproducibility tarball released alongside the paper.

## 6. Statistical Reporting Standard

For any quantitative claim:

- Report mean ± **95% BCa bootstrap CI** (n = 1000, BCa method).
- For "X beats Y" claims: paired Wilcoxon signed-rank with Holm-corrected p-values.
- Effect size: median per-question difference.
- Always disclose: number of seeds, judge model, sample size.
- Numerical precision: 2 decimal places for ratios; 3 for p-values; appropriate units for cost ($) and latency (ms).

A `tools/stat_check.py` script audits the draft LaTeX file: every `\X.YZ` claim must trace back to a value in `runs/_aggregated/leaderboard.csv` or a derived stats file.

---

## 7. Prompt & Hyperparameter Disclosure

Appendix includes:

- **Full prompt templates** for every technique, judge, and indexing pipeline. Hashes match those in run manifests.
- **Hyperparameter table** per technique (k, chunk size, rerank top-k, agent step cap, etc.).
- **Model versions** with exact API timestamps.
- **Dataset cards** for each domain (source, license, size, hash).
- **Compute breakdown** (total $, total tokens, total wall-clock, total GPU-hours).

This disclosure is the bare minimum for reproducibility and is a requirement of most major venues.

---

## 8. Reproducibility Package

A submission-time `repro/` tarball contains:

- `runs/_aggregated/` (all derived metrics, leaderboards).
- A subset of representative `runs/<id>/` (manifest + outputs.jsonl + metrics.json) — at least one per (technique × domain) cell.
- All code at the submission-time git SHA.
- All Hydra configs.
- All prompt templates.
- A `REPRODUCE.md` with step-by-step "how to re-run" instructions.

Built by `scripts/build_repro_tarball.sh`. Targets ≤ 500 MB compressed (excluding raw corpora, which are linked rather than embedded).

## 10. Writing Workflow

1. **Phase 12 ends with `FINDINGS.md` synthesis.** Every paper claim originates as a Findings entry.
2. **Outline → Section drafts → Stitching.** Author each section as a standalone Markdown file under `paper/sections/`, then stitch into a single LaTeX document.
3. **Figures regenerate from notebooks** every time the underlying runs change.
4. **Tables regenerate from CSVs** via `scripts/regenerate_tables.py`.
5. **Internal review checklist.** Self-review against `paper/REVIEW_CHECKLIST.md`:
   - Every numeric claim has CI / p-value.
   - Every figure caption is self-contained.
   - Limitations honestly listed.
   - No "novel" without comparison; no "best" without statistical test.

## 11. Limitations Section (Pre-Committed Honest Inventory)

The paper will explicitly disclose:

- **Judge-model bias.** Most generators tested are Gemini-family; the primary judge is also Gemini. Mitigated by GPT-4o cross-check on a subsample.
- **Synthetic Q&A.** Some benchmarks are LLM-generated. Mitigated by the 100-question human-judged sub-sample per domain.
- **Cost-volatility.** Provider pricing changes; results depend on a price snapshot. Mitigated by reporting raw token counts alongside $.
- **Domain coverage.** 7 domains is broad but not exhaustive. Mitigated by transparent dataset cards.
- **Out-of-scope techniques.** KV cache compression, SWA, SSMs are documented but not benchmarked. We report literature numbers for context.
- **Single-LLM family.** Most non-RAG / Generator slots are filled with Gemini. We supplement with one Ollama-hosted model for ablation, but cross-family generation is limited.

## 12. Negative Results Plan

If a hybrid loses to its baselines, we **publish that anyway**. Negative results in a comparative paper are valuable. The Discussion will note them explicitly with hypothesized causes.
